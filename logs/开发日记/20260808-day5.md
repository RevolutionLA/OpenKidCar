## 今天做了什么（远程可做的）

### ① twin_server 加 --real-serial 真实串口模式
数字孪生原本**硬编码 CerebellumSim（模拟小脑）**，接真实 Arduino 需要改造。今天加了：

- `RealCerebellum` 类：接口对齐 CerebellumSim，真实模式下命令发给 Arduino、状态从 STAT 帧解析
- `--real-serial <串口>` 启动参数：`twin_server.py --real-serial /dev/ttyACM0` 直连 Arduino
- **关键理解**：真实车辆油门/刹车是小孩踩物理踏板 → Arduino 直读 A0/A1 → 本地驱动，**不经过大脑**（协议里没有 THROTTLE/STEER 命令）。网页的油门/刹车只是仿真。

### ② 虚拟化验证小脑固件（native 测试 20/20）
没有 Arduino 也能测固件逻辑！做法：
- main.cpp 加 `#ifdef UNIT_TEST` 测试钩子（暴露 handle_command 和全局状态）
- platformio.ini native 环境加 `test_build_project_src = yes`（让 pio test 编译 src）
- test_frame.cpp 追加 10 项固件命令逻辑测试：GEAR/LIGHT/STRIP/MUTE/BRAKE/EBRK/未知命令
- **发现并修掉 2 个测试框架 bug**（setUp 没重置全局状态 → 后续测试串扰）

结果：**20/20 通过**（协议 10 + 固件逻辑 10），上板前固件逻辑已验证。

## 补：PRD 功能对照核查 + 补 P0/P1/P2 缺口

对照 [product_requirements.md](../docs/product_requirements.md) 核查，发现 P0/P1/P2 有几个缺口，当天补齐：

### P0 家长远程设档位（F-DRV-04 / F-APP-01）
- 后端 `handle_parent_command` 加 `gear` 命令 → `brain.set_gear()`
- 家长端加"远程档位"D1-D4 按钮（高亮当前档位）
- 测试：家长设 D3 → 小车档位变 3 ✅

### P1 智能上下电（F-PWR-01/02）
- CerebellumSim 加 `set_seat()` + `seat` 状态（对应真实坐垫压力 A2）
- 家长端加"⚡ 上电/下电"按钮 + 车辆状态区"电源"显示
- 测试：上电→seat True，下电→False ✅

### P2 轨迹回放（F-GPS-03 / F-APP-07）
- 后端 `_update_gps` 记录 `gps_history`（去重，车不动不重复记，限 500 点），state 下发
- 家长端"⏪ 回放轨迹"按钮：Canvas 动画逐点回放历史轨迹
- 测试：轨迹历史记录正确 ✅

**经验**：PRD 对照是发现"没做完"的好方法 —— 一个功能一个功能对着需求查，比凭感觉判断全面得多。

### 倒车 R 档功能（补漏）

用户发现系统没有倒车（档位只有 D1-D4 前进）。补全 R 档，贯通全链路。

**决策**：R 档传输用数值 `-1`（UI 显示 R）；真实硬件用**双向电调**（脉宽 1000-2000us）。

**各层改动**：
- 协议：GEAR 参数扩为 `-1(R) / 1-4`，文档 V0.4
- 大脑：`set_gear` 校验 `-1<=gear<=4`
- 小脑固件：g_gear 存 -1、drive_motor 反向、estimate_speed 负速度、GEAR 校验排除 0
- HAL：`hal_set_motor` 改为 `int -100..100`（负=倒车，双向电调脉宽）
- 仿真小脑：GEAR_SPEED_MAX + R_SPEED_MAX=6、负 target、刹车按方向钳位
- 孪生后端：家长日志显示 R、GPS 倒车反向移动
- 前端：小车/家长端加 R 按钮（data-g="-1"）、速度表负值、档位显示 R

**验证**：固件 native 21/21（新增 R 档用例）、大脑 15/15、端到端设 R→speed 负→GPS 反向 ✅。视觉确认 R 按钮渲染 ✅。

**经验**：档位这种"纯限速"设计天然没有方向概念，加反向要横跨协议→大脑→固件→HAL→仿真→后端→前端全链路，且硬件电机必须支持反转（双向电调）。
