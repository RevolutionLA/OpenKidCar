## 踩坑记录（今天修掉的 bug）

1. **aiohttp `add_static("/", dir)` 404**：挂载根路径在 aiohttp 3.14 行为异常。改为显式 `add_get("/")` 返回 index.html + `add_static("/static")` 服务其余资源，干净可靠。
2. **`ws.send_str()` 是异步协程**：在转发对讲/视频时忘记 `await`，导致消息从未真正发出（报 RuntimeWarning）。→ 改成 async 函数 + `await`。
3. **DOM `childNodes[2]` 越界**：家长端在线状态 chip 的 childNodes 只有 2 项，索引 2 是 undefined，导致整个状态渲染中断（GPS 全不显示）。→ 改用独立的 `<span>` + `textContent`，不依赖脆弱的节点索引。
4. **headless Chrome 验证的假象**：`--virtual-time-budget` 会"冻结真实时间"，导致 WebSocket 消息在虚拟时间模式下送不到，页面显示"没渲染"。**这不是 bug，是验证方法的坑**。最终用 Node 原生 WebSocket 以浏览器视角直连，确认数据链路畅通。

## 小白问答沉淀（今天的）

1. **为什么要"一个进程开两个网页"，而不是两个独立程序？** —— 因为两个孩子/家长端要看到**同一辆车**。两个程序各跑一套大脑小脑，状态就分叉了。共享一个核心，才保证"真"。
2. **对讲机"按住说话"是怎么实现的？** —— 按下时用 MediaRecorder 录音，松开时把录音 blob 通过 WebSocket 发给对方，对方用 `<audio>` 播放。是真实的音频管线，不是假象。
3. **视频通话没有 WebRTC 也能做？** —— 可以。用 canvas 每 0.2 秒截一帧摄像头画面（JPEG），通过 WebSocket 发给对方实时显示。局域网下完全够用，还更简单可靠。
4. **GPS 是模拟的吗？** —— 是。真实硬件里 GPS 来自树莓派接的 4G/GPS 模块；现在没有硬件，就在大脑层模拟：车速越快，坐标移动越快，行驶中缓慢转弯形成轨迹。
5. **电量也是模拟的？** —— 是。真实小脑通过 ADC 上报电池电压；现在在小脑模拟层让它按负载（油门）消耗，电压换算成百分比，家长端就能看到"掉电"。

## 速度环"常亮蓝弧" bug（SVG dasharray 原理）

用户框出"速度0时外圈却有一段蓝色弧"，以为是没用的装饰。真相是**速度进度弧的 SVG 写法错了**：

- 错误写法：`stroke-dasharray: 433.5`（dash 段固定占圆周 75%）。闭合圆上 dash 段永远显示，**弧和 offset 无关，永远显示 270°**。
- 正确写法：**JS 动态设置 dasharray** —— `dash = 弧长×速度比例，gap = 周长−dash`，offset 固定 0。速度 0 → dash 0 → 完全隐藏；满速 → dash 433.5 → 270°。
- 验证：像素级确认速度 0 弧 0°、速度 10/15 弧约 180°、速度 0 又归 0°。

**经验**：SVG 环形进度条，`dasharray` 的 dash 段长度必须随进度**动态变化**，不能固定值 + offset 旋转。

## 第二轮体验反馈修复（音效 / 控制区 / 单向视频）

1. **音效无声**：Web Audio 引擎轰鸣 + 喇叭在点击时无声。根因：浏览器自动播放策略把 `AudioContext` 挂起（suspended），需在用户手势后 `resume()`。修复后：`initAudio()` 检测到 suspended 就 resume；并把引擎声音量曲线改为"油门 0 几乎无声、油门越大越响"。
2. **控制区重布局**：油门/刹车 → 竖向瘦长滑块（`writing-mode: vertical-lr`）；转向手柄 → 横向瘦长；8 个功能按钮（大灯/静音/灯带/喇叭/急刹/语音/视频/对讲）统一为 2×4 等大小方块（含按住对讲）。
3. **视频改为单向视频、双向语音**：小车端只推自己的摄像头画面给家长，不再接收/显示家长视频流；家长端只显示孩子画面、不推自己的视频；对讲（PTT）仍双向。
4. **电池消耗速率调低**：原来约 42 分钟耗尽太夸张，调整为约 5.5 小时，演示更真实。
5. **链路测试增强**：`test_ws_link.py` 的急刹项改为等待状态同步（修掉时序竞争，6/6 稳定通过）。

**经验**：浏览器无声类问题，90% 是 `AudioContext` 没 `resume()`（autoplay 策略），不是引擎代码错。

### 控制区再调整（第三轮）：操控杆加长 + 按钮排两侧

用户反馈控制区有空白、杆太短。改为"驾驶舱"三分布局：

- **中间**：油门、刹车两个竖向长杆（426px，约占控制区 2/3），随高度 flex 拉伸
- **左右两侧**：各 4 个统一大小按钮竖排（左：大灯/静音/灯带/喇叭；右：急刹/语音/视频/对讲）
- grid 三列 `1fr auto 1fr`，DOM 精确验证：左右对称、杆长、无空白无重叠

**经验**：验证布局要设置与用户一致的视口（Emulation.setDeviceMetricsOverride），否则默认小视口触发响应式布局，坐标全错。

### 控制区再调整（第四轮）：杆与按钮等高 + 整体居中

用户反馈竖杆 426px 太长（比按钮长一倍）、周围大量空白。用 DOM 精确测量发现：主区 flex:1 撑满 447px，杆撑满导致超长，按钮只有 200px 悬在中间。

修复：杆固定 240px 与按钮列完全等高（4 按钮 padding 15px），主区 `align-items: center` 让杆+按钮整体垂直居中，上下留白对称（105/127→93/93）。视觉确认"布局协调"。

**经验**：控件高度不匹配是"大量空白"的根源 —— 元素等高 + 整体居中，留白自然对称。

### 第五轮反馈修复（音效真实化 / 转向灯联动 / 语音常开 / 家长端）

1. **引擎声、喇叭声真实化**：Web Audio 合成声太假。引擎改用真实 CC0 录音 `engine.mp3`（Audio 元素 loop，油门越大 `playbackRate` 越高）；喇叭从 BigSoundBank 下载 CC0 汽车鸣笛 `horn.mp3`（`/UPLOAD/mp3/3436.mp3`）。开源 CC0 音效源：BigSoundBank、Chosic、爱给网、Pixabay。
2. **转向灯联动转向手柄**：左转/右转指示灯之前从没亮过（无输入源）。改为 `set_steer()` 自动联动：手柄打左→`turn=L`、打右→`turn=R`、回中→关闭。现在转向灯真正反映转向。
3. **语音开启即常开**：之前每条指令后自动退出唤醒态，导致"说指令没反应"。新增 `always_awake` 模式：开启语音后直接说指令（「打开大灯」「三档」），且持续有效。vosk 识别验证 5/5 通过。
4. **家长端视频窗格按需显示**：不点视频时只显示"视频通话"按钮，点击后才显示画面窗格（DOM 验证 display:none→block）。
5. **家长端 UI 优化**：电量参数间距加大、字体放大；底部对讲/急刹按钮对比度增强（蓝/红更醒目）。

**经验**：语音识别"没反应"要先分清是识别没开、唤醒词没触发、还是指令匹配失败 —— 用 `_handle_text()` 单测可快速定位。

### 第六轮修复：喇叭声换源 + 视频 hangup 循环 bug

1. **喇叭声仍不对**：BigSoundBank 的"Car honking at 90 km/h"是行驶风噪，不像喇叭。换为 freesoundslibrary 的 **Car Horn Honk on the Street**（38KB，2 秒干净喇叭声）。
   - 来源：https://www.freesoundslibrary.com/car-horn-honk-on-the-street-sound-effect/（**CC BY 4.0，需署名**）
   - 其他 CC0 喇叭源：Creazilla（Freesound 转存，被 Cloudflare 挡）、Chosic、爱给网。
2. **事件日志一直刷"视频推送已停止"**：`stopVideoCall()` 里发 hangup，收到 hangup 又调 stopVideoCall 又发 hangup —— **两端无限循环**。修复：两端加状态标志（小车端 `pushing`、家长端 `inCall`），只在通话中才响应 hangup 并发送一次，循环中断。

**经验**：消息类逻辑，任何"收到消息→处理→发消息"的路径都可能形成回环 —— 加状态守卫（只在需要时发）是标准解法。

### 第七轮：引擎声逻辑重写（油门 0 无声 / 急刹停声 / 速度变频）

引擎声规则改为：
- **油门 0 或急刹/深刹车** → 完全无声（真实车辆急刹松油门）
- **油门越大** → 音量越大（0 ~ 0.4）
- **速度越大** → 音调越高（`playbackRate` 0.6 ~ 1.5，真实录音变速）

用 CDP 暴露 `window.engineAudio` 实测验证：
- 油门 100 → `volume=0.400`、`rate=1.26` ✅
- 刹车 100 → `rate=0.50`（stopping 分支）✅
- **`mute=True` 时 volume 恒 0** —— 静音功能正确把引擎声静掉，用户反馈"完全没变"很可能是静音开关被打开了

新增开发工具 `tools/test_engine_audio.py`：CDP 驱动滑块 + 读 engineAudio 状态验证音效逻辑。

**经验**：音效"没反应"先查三个开关 —— 静音(mute)、在线(online)、急刹(stopping)，再查 volume/rate 设置。

### 小智语音对话集成（数字孪生网页按钮触发）

把真实小智 AI 助手接进数字孪生：小车端加"📡 小智"按钮，**按住说话 → 网页麦克风 PCM → 后端转发小智官方服务器 → 小智语音回复回传网页播放**。

**架构（双进程）**：
- `digital_twin/backend/xiaozhi_bridge.py`（独立进程，py-xiaozhi 3.11 venv，端口 8010）：复用 `WebsocketProtocol` + `OpusCodec`，连小智官方服务器（`wss://api.tenclass.net/xiaozhi/v1/`）
- `twin_server.py` 加 `XiaozhiBridgeClient`：连本地 8010，把小车端 xiaozhi 消息转发，回复推回小车端（`broadcast_to_kids`）
- 前端：`#btn-xiaozhi` 按住说话，AudioContext 采 16kHz PCM → base64 → 发 `xiaozhi/audio`；收 `xiaozhi_reply`（24kHz PCM）→ 拼 WAV → `<audio>` 播放

**协议要点**（小智官方协议）：
- 发出去：16kHz 单声道 Opus（20ms/帧=320 样本），`send_start_listening(MANUAL)` → `send_audio` → `send_stop_listening`
- 收回来：Opus 帧（`parse_opus_toc` 探测帧时长）→ 24kHz PCM

**验证**：`tools/test_xiaozhi_bridge.py`（直连桥接）+ `tools/test_xiaozhi_e2e.py`（走 twin_server 全链路）都收到小智回复（11 块/10560 字节）。端到端 ✅

**启动**：`scripts/start_xiaozhi.bat` 一键起 twin_server + 桥接。

### 干杯助手回复音质优化（clip + 流式播放）

1. **电音/爆音**：桥接 `float32 → int16` 没做 clip，Opus 解码超 ±1.0 溢出爆音 → 加 `np.clip`。
2. **一卡一卡**：前端把每块 20ms 回复单独 new Audio 播放 → 间断卡顿。先改"累积整段 WAV 一次播"（丝滑但时延长），用户反馈时延太长 → 再改 **Web Audio 流式播放**：
   - 每块到达 → 立即转 AudioBuffer → 按 `AudioContext.currentTime` 时钟排到"上一块结尾"播放
   - 第一块立刻播（低延迟），后续块无缝衔接（不卡顿）
   - `xzNextStart` 记录下一块开始时刻；TTS 结束（`xiaozhi_tts_end`）重置
   - int16→float32 注意有符号转换（`v>=32768 → v-=65536`）

**经验**：实时语音"低延迟 + 不卡顿"要用 Web Audio 时钟精确调度（`source.start(when)` 排到上一块结尾），而非整段拼装或每块独立播放。
