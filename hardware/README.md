# 硬件层：现状与计划

这个目录对应 README 里「硬件、固件、电路到软件完全由你掌握」的承诺。**诚实地说：软件层（大脑 + 小脑 + 数字孪生）已可跑起来，硬件设计稿目前为空。**

| 目录 | 内容 | 状态 |
|---|---|---|
| `bom/` | 物料清单（车架、电机、电调、舵机、电池、传感器、线束） | 🚧 规划中：先把 V0.1 电控原型的最小 BOM 定稿 |
| `circuit/` | 电路原理图（电源分配、急停回路、信号电平转换） | 🚧 规划中 |
| `pcb/` | PCB 工程文件（可选：先面包板 + 洞洞板验证，PCB 放在 V0.2） | 🚧 规划中 |
| `../cad/body_design/` | 车体结构（3D 模型 / 图纸） | 🚧 规划中 |

## 为什么先空着而不是先画图

V0.1 的目标是「在没有真车的情况下验证信号链路」，这件事已经由 `firmware/arduino`（小脑，含 native 协议测试）和 `software/raspberry_pi/digital_twin`（数字孪生双端）完成。硬件图纸一旦先画，就会在没有实测的情况下反复改版——**先让协议和逻辑跑通，再定电路，返工最少**。

## 想参与的硬件同学

1. 先读 [`docs/architecture.md`](../docs/architecture.md) 与 [`docs/communication_protocol.md`](../docs/communication_protocol.md)，把 IO 映射与协议搞清楚；
2. 从最小 BOM 开始提 PR（一个 `bom/v0.1-minimal.csv`，列：物料 / 型号 / 数量 / 单价 / 采购链接 / 备注）；
3. 电路图用 KiCad 或立创 EDA，源文件直接入库（不要只放 PDF），并在本文件补一行状态表。

> 采购/接线类问题请走 issue 模板；实物照片欢迎直接贴进 issue。
